# 3 分钟演示视频脚本（优化版）

> 核心叙事：从“拍照讲解”升级为“可验证、可追问、可行动，还适合带孩子”的旅行讲解助手。

## 时间分配

| 时间 | 内容 | 重点 |
|---|---|---|
| 0:00–0:15 | 痛点 | 看不懂、导游贵、讲解千篇一律 |
| 0:15–0:35 | 产品亮相 | 拍一张照片，得到可验证讲解 |
| 0:35–1:20 | Demo 1：太和殿 | 识别 + 分层 + 来源 + 置信度 |
| 1:20–1:50 | Demo 2：亲子模式 | 儿童版 + 任务卡 |
| 1:50–2:20 | Demo 3：兵马俑 + FlyAI | 真实 POI/门票 + jumpUrl |
| 2:20–2:45 | 技术亮点 | 百炼 + Qwen-VL + flyai skill + 知识库 |
| 2:45–3:00 | 市场与结尾 | 用户、商业化、Slogan |

---

## 0:00–0:15 痛点

**画面**：游客在景区看牌匾、人多的导游团、手机里杂乱的攻略页面。

**旁白**：
> 自由行到了景区，牌匾看不懂，历史不了解，请导游又贵，网上讲解千篇一律。  
> 如果拍一张照片，就有一个懂历史、会讲故事的私人讲解员呢？

## 0:15–0:35 产品亮相

**画面**：产品首页，标题「随行讲解员」，拍照按钮和示例问题。

**旁白**：
> 这是随行讲解员，基于阿里云百炼和飞猪 FlyAI 打造。  
> 拍一张照片，它会先识别，再告诉你哪些是史实、哪些是传说、哪些还需要考证，并给出每一个结论的来源。

## 0:35–1:20 Demo 1：太和殿

**画面**：
1. 上传太和殿照片。
2. 展示识别结果、置信度和识别依据。
3. 选择“3 分钟标准版”。
4. 展示【史实】【传说】【待考证】和来源。
5. 点开来源卡片。

**旁白**：
> 我上传一张太和殿照片。它识别出这是故宫太和殿，置信度很高，并说明识别依据。  
> 讲解不是一大段无法核验的文字，而是结构化的主张：每条信息都有类型、来源和置信度。  
> 比如“太和殿是中国现存最大的木结构大殿”标注为史实，来源是故宫博物院官网；民间俗称“金銮殿”的误解则标注为传说。

## 1:20–1:50 Demo 2：亲子模式

**画面**：
1. 追问“带孩子怎么讲？”
2. 展示儿童版讲解。
3. 展示亲子任务卡：观察任务 + 3 个问题。

**旁白**：
> 如果我是带孩子的家长，只需要问一句“带孩子怎么讲？”  
> 它就会切换成儿童版，用孩子能听懂的方式重新讲，并且生成一张亲子任务卡：找一个细节、回答三个问题。  
> 讲解就从“听”变成了“玩”。

## 1:50–2:20 Demo 3：兵马俑 + FlyAI

**画面**：
1. 上传兵马俑照片，识别成功。
2. 追问“附近还有什么值得看？怎么订票？”
3. 展示 FlyAI 返回的华清宫、一日游、门票和 `jumpUrl`。
4. 点击跳转预览。

**旁白**：
> 讲解完之后，用户还可以直接问：“附近还有什么？怎么订票？”  
> 它会调用飞猪 FlyAI，返回真实的 POI、门票和玩乐信息，并给出可以点击的预订链接。  
> 这样，讲解不只是信息，而是能直接推动下一步行动。

## 2:20–2:45 技术亮点

**画面**：架构图逐层点亮：百炼 Agent → Qwen-VL → 知识库 → Qwen-Plus → flyai skill。

**旁白**：
> 技术上，作品使用阿里云百炼 Managed Agent，调用 Qwen-VL 做图像识别和牌匾 OCR，用 Qwen-Plus 结合知识库生成结构化讲解。  
> 通过飞猪官方 flyai skill 接入真实旅行数据；同时对高频结果做缓存，保证演示速度和成本可控。

## 2:45–3:00 市场与结尾

**画面**：用户图标：自由行、亲子家庭、入境游客；商业路径：景区合作、门票/玩乐佣金、内容服务。

**旁白**：
> 它面向自由行游客、亲子家庭和入境游客，也可以和景区、博物馆合作。  
> 随行讲解员，让每一次旅行，都有一个懂它的人陪伴。谢谢观看。
